Let's design a complete CRM system for Andexor Network. I want 2 separate apps in 3 repos. One app for the front-end web UI, built with Next.js. One app for the back-end services, built with FastAPI and using D1 for the database and having the same kind of gated preview CI/CD pipeline as my other services. Both to be deployed to Cloudflare. Use my GitHub projects andexor-net-website, andexor-net-website-contact-us, and andexor-net-website-ping for references on architecture and design choices. You may take some liberties with the front-end design to make it beautiful, usable, modern, and engaging, but it must also conform to the style of andexor-net-website enough to immediately conclude that they are related when looking at them for the first time. The third repo is a "*-main" one containing overall documentation and a common data model for both apps to follow. Create a master PRD in the main repo and individual PRDs for the front-end and back-end apps. Use SpecKit for all of them. The first thing we need to do is brainstorm a name for this system. The name must start with "Andexor". After that, perhaps some words that would form the acronym "CRM", though that is not required. Ask me lots of questions along the way as we build each of the PRDs, but also keep it simple. I want it to be easy to use, with as few required fields as possible. The system needs to be able to track data related to initial lead info, enriched lead data, a qualification rubric, which will vary according to which services they might need and which services I can provide, a lead scoring feature to help me decide whether they are worth reaching out to or not, more data for a prospect as I meet with them and learn more about them, and full customer relationship management. To whatever extent is necessary for a CRM, it needs to support engagement models like one-time contracts, monthly recurring retainers, and performance-based work, and a Master Services Agreement along with other agreements for specific statements of work.
